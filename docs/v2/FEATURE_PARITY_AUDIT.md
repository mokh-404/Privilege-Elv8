## 2. Specific Verification Notes on High-Risk Features

1. **`file_entropy` vs `file_size_log` (No v1-vs-v2 Window Mismatch Found):**
   - Inspection of [`collector/Collect-Artifacts.ps1:185-205`](../../collector/Collect-Artifacts.ps1#L185-L205) and `data/raw/runs/ctrl_01/artifacts.json` confirms v1 **already** read `$bufSize = 1048576` bytes once (`if ($firstChunk -and $null -ne $hist)`) for `file_head_histogram` while recording full `[int64]$fi.Length` for `file_size` (`75 / 1,076` `ctrl_01` records exceed `1 MiB`).
   - Thus v2's leading `1 MiB` histogram (`1 << 20` bytes) + full `$DATA` size **matches v1 identically** on readable files. The only divergence is missingness: v1 missed `file_entropy` on `27 / 444` locked `dev` `file` rows (e.g., locked system/profile binaries), which cannot be recovered from `data/raw/` alone; v2 dual-config (`full_20` + `no_content`) directly prevents `file_entropy` missingness from deciding winners.
2. **`signature_state` (Catalog Signing + `UnknownError -> na`):**
   - In `ctrl_01` raw records (`n = 1,076`), `signature_status` was `Valid: 588`, `UnknownError: 303`, `NaN/None: 180` (non-file registry/WMI/shimcache/account rows + missing files), `NotSigned: 5`.
   - `Valid` includes OS inbox binaries without embedded PE Authenticode (`svchost.exe`, `cmd.exe`, `rundll32.exe`) whose SHA-256 Authenticode hash is registered in `C:\Windows\System32\CatRoot\{F750E6C3-38EE-11D1-85E5-00C04FC295EE}\*.cat`. Offline extraction MUST parse both embedded PE signatures and `CatRoot` `.cat` catalogs (`signify`), AND map non-SIP extensions to `UnknownError -> na` identically to `Get-AuthenticodeSignature`.
3. **`cmdline_*` Formatting Quirks (`service`, `run_key`, `registry`):**
   - [`Collect-Artifacts.ps1:359`](../../collector/Collect-Artifacts.ps1#L359) deliberately passed `DoNotExpandEnvironmentNames` on `run_key` values (e.g. `%windir%\system32\SecurityHealthSystray.exe`), whereas `Win32_Service.PathName` (L343), `Winlogon`/`IFEO`/`UAC` (L438–L471), and `Expand-NormPath` expanded env vars. Replicating that rule offline avoids artificial `%Var%` string-length / non-alphanumeric drift.
   - Because [`data/raw/runs/`](../../data/raw/runs/) retains the raw collector JSON, v1 `emulated` `command_line` / `file_head_histogram` features are also auditable if `emulated` recomputation is ever needed; however, matching the v1 rule offline requires **zero** alteration to frozen `dataset_v1.parquet`.
